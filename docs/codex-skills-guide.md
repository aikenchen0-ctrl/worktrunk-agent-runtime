# 三个 AAR 协作 Skill

> 文档中的用户目录已匿名化；示例绝对路径须按实际机器替换。

## 作用范围

三个 Skill 复用现有 `agentctl`、验证脚本、Gradle、GitHub 工具和获准的宿主任务工具，不新增 Rust 发布机器人或后台服务。

| Skill | 负责 | 不负责 |
| --- | --- | --- |
| `aar-candidate` | 分析契约、准备候选、验证发布、生成事件交接 | 消费者迁移、稳定发布批准 |
| `aar-upgrade` | 升级固定候选、迁移调用、生成收据、按授权交付草稿 PR | 自动合并、伪造验证、修改其他 Worktree |
| `aar-coordinate` | 查询状态、核对映射、向已授权任务通知、组织组合验证 | 无授权广播、常驻唤醒、分布式消息可靠性 |

它们是按需执行的操作规程，不是已经打通跨机器身份、远端制品发布或自动消息服务的证明。安装不包含发布、推送、建 PR 或向其他任务发送消息的授权。

## 文件与安装

工程源文件：`F:\code\worktree\agent-runtime\skills\aar-candidate`、`aar-upgrade`、`aar-coordinate`。

本机安装目标：`C:\Users\developer\.codex\skills\aar-candidate`、`aar-upgrade`、`aar-coordinate`。每个目录包含 `SKILL.md`、`agents/openai.yaml` 和 `references/workflow.md`。在同一账户的其他仓库使用安装副本；工程目录保留可维护源文件。

不要同时把同名副本安装到用户目录、业务仓库和其他发现目录。修改工程源文件后需要有意识地更新安装副本并核对摘要，不把两个副本当作自动同步。

当前用户使用既有 `~/.codex/skills` 安装约定。新的 Codex 部署可按其官方发现规则使用 `~/.agents/skills`；迁移时保留一个可发现安装位置，避免同名重复。Skill 不修改 Codex 私有数据库或配置。

## 如何调用

在负责某模块的 Codex 任务中输入：

```text
$aar-candidate
为当前模块准备候选，比较已发布基线，更新接口与迁移说明。
先完成本地构建和检查；远端发布目标与权限尚未确认，不上传。
```

已有真实事件时，在消费者拥有的迁移 Worktree 任务中输入：

```text
$aar-upgrade
处理我提供的候选事件文件，核对消费者身份，升级固定依赖并迁移调用。
运行正式验证后汇报收据；本轮先不推送或创建 PR。
```

在协调任务中输入：

```text
$aar-coordinate
汇总当前候选、已迁移消费者、未完成验证和需要处理的 PR。
先核对任务映射；本轮只读汇总，不向其他任务发送消息。
```

启用完整流程时，明确指定发布仓库、消费者、可推送目标分支、可通知任务和负责协调的执行者。例如可以授权“将这一组已登记候选协调到列出的消费者任务，并允许创建升级草稿 PR；禁止合并和正式发布”。不要靠在文档中写 `authorized: true` 代替用户授权。

如果 Skill 菜单尚未显示，重新打开任务或重启 Codex 后检查。也可要求 Agent 读取安装目录中的完整 `SKILL.md` 执行，不能声称当前任务已经自动重载。

## 与 AGENTS.md 配合

项目规则只保留身份、隔离、证据、授权和稳定主线门槛，并按任务类型引用三个 Skill。`examples/AGENTS.md` 是接入模板，不应覆盖业务仓库已有规则。无需每轮重写所有接口文档，也不要求所有模块预先冻结 API。

独立下载 Gradle、插件和依赖是允许且推荐的隔离方式；快照导入是可选优化，不是使用 Skill 的前置要求。

## 首次试点

1. 一个提供方任务准备并在获准目标发布固定候选，完整可读后创建事件。
2. 一个消费者任务迁移并通过 `validate-candidate.ps1` 产生真实收据。
3. 一个协调任务只读核对状态；确认映射与通知授权后，才测试定向消息。
4. 若获准创建 PR，固定工作项和唯一执行者，核对真实 PR 头提交的 CI。
5. 最后跑固定候选集合的组合验证；不以单仓通过代替发布批准。

当前跨机器身份与可信 CI 收据仍有缺口；遇到这些限制时应报告，不修改事件绕过。通知工具与 GitHub 权限不存在时，Skill 只能输出交接和草稿。

## 核验边界

基础验证应覆盖三个技能的 YAML、名称、引用文件、PowerShell 示例语法和安装副本摘要。另需审阅候选重复发布、PR 并发创建、消息无授权、伪造收据和跨机器路由等失败路径。

结构校验和静态审阅不等于真实远端发布、GitHub PR 或多任务通知实测。本次安装不执行这些外部动作。
