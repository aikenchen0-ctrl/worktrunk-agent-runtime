# 并行模块研发需求基线 v2

本需求依据 2026-09-26 的真实 Android 测试与用户确认更新。阶段实现不等于全部验收完成。

## 不变目标

多个独立模块仓库由不同 Agent 并行开发；API 可持续变化和发生破坏性变化。每仓独立构建，失败升级不改变其他仓的稳定依赖。Worktrunk 核心和 Git 行为不修改。磁盘可换取私有依赖副本，设备按租约使用。

## 需求与验收

| 编号 | 要求 | 可观察验收 |
| --- | --- | --- |
| R1 | 不阻塞指稳定开发不受候选升级影响 | 提供方改接口后，消费者固定旧组合仍能构建；候选失败仅阻止对应升级 |
| R2 | 构建状态隔离、协作状态统一管理 | Gradle/Maven/测试 JVM/临时目录按 Worktree 隔离；设备和端口在统一根目录互斥；超时只回收对应进程树 |
| R3 | 版本化契约交接 | 提供方记录提交、签名与语义变化、迁移步骤、候选坐标和摘要；草稿不能当作已发布实现 |
| R4 | 通知可恢复、可去重 | 区分产生、送达、接手、验证、合并和晋级；离线补读，重复或乱序不重复执行升级 |
| R5 | 实际依赖组合验证 | 收据绑定提交、变体、候选组合、实际解析结果和规则版本；识别传递依赖和源码/制品混用 |
| R6 | 结果有证据、有归因 | 区分编译、行为、集成和设备检查；区分已有失败、新增失败、环境故障与未完成检查；豁免有范围和有效期 |
| R7 | 角色清晰 | 本机控制器管理资源；协作层管理任务和状态；发布集成层管理制品、升级 PR、稳定组合及回滚 |
| R8 | 最终规模演练 | 十几个真实独立仓库分别改 API，验证旧组合可用、迁移成功、组合冲突、消息故障、崩溃恢复和回滚 |

本机同账户协作约束不等于操作系统安全沙箱。防恶意绕过需要独立账户或可信 CI 权限，是另一个部署边界。

## 状态模型

候选已发布、Agent 已收到、消费者验证通过、升级已合并、组合已验证、稳定版本已晋级是不同事实。每个状态记录其证据和作用范围，不能从前一个状态直接推导后一个状态。

单候选验证不能推导多候选组合兼容。组合验证结果仅对明确的输入快照与消费者提交有效；它是下一步发布验收的输入，不直接授权发布。

## 当前优先顺序

1. 完整验证证据、组合验证、失败归因。
2. 各仓实际依赖图和迁移状态。
3. 通知连接器、任务交接、升级 PR 自动化。
4. 十几个独立仓库的规模验收与稳定组合回滚。

不将目前的两小时租约、JVM Test 适配器、命令名称等实现选择固定为业务约束。后续添加设备和其他验证器时，保持证据身份、状态隔离和失败保守处理的要求。
