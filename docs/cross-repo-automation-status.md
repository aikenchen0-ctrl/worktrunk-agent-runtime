# 跨仓发布、Codex 通知与升级 PR 状态

核对日期：2026-09-27。本文件区分已实现、已验证与待实现，不是已上线能力清单。

## 当前实现

| 能力 | 已有证据 | 尚未接通 |
| --- | --- | --- |
| 候选发布 | 本机目录 Maven 测试发布；候选坐标及实际解析制品摘要验证 | 远端制品仓库发布事务、服务端禁止覆盖、完整发布确认及自动事件生成 |

| 升级 PR | 手动触发的消费者 CI 模板 | 自动创建分支、依赖修改、PR 去重创建、自动触发验证与状态回收 |

本轮没有向其他 Codex 任务发送消息，没有创建 GitHub PR，也没有执行远端候选发布。任务可列出不等于自动通知已经实测。

## 本次发现的边界问题

1. 发布脚本中的目录存在性检查不是远端不可覆盖保证，并行检查与写入仍有竞争窗口。生产发布必须由制品仓库或受控发布事务保障同坐标不可覆盖。
2. 事件保存本机绝对路径，异机 runner 的 checkout 路径不同。直接导入事件不等于能够匹配消费者，也不能靠改写旧事件绕过身份检查。
3. 原 README 把候选发布前创建事件与可供验证混在一起。现已改为先确认制品完整可用，再产生可验证候选事件；接口草稿通知应是独立阶段。
4. 原 README 对 CI 模板能力描述过满。现已明确其不包含跨仓分发、自动 PR 或任务通知。
5. 宿主消息工具属于当前 Codex 环境能力，普通 agentctl 进程没有因此自动获得调用入口。需要明确的桥接适配器，不能读取或修改 Desktop 内部状态文件来假装已经接入。

## 下一阶段实施顺序

### 1. 统一身份与候选就绪事件

- 用远端平台、稳定仓库标识、模块和变体标识跨机器身份；本机路径仅作为工作目录映射。
- 记录完整 Git 提交、构建编号、候选坐标、AAR/JAR、POM、模块元数据摘要与实际依赖版本。
- 制品全部上传并经消费者视角验证可读后，提交候选就绪记录和待发送事件。
- 使用持久发送队列；发布成功但通知失败可补发，通知重试不能重新覆盖制品。
- 当前路径身份事件保留原语义；新协议显式版本化，不静默修改历史事件。

### 2. Codex 任务通知适配器

- 登记消费者、仓库、Worktree、Agent ID、host_id、thread_id 和已授权的任务范围。
- 持久化待发送、已送达、已确认接收和处理结果；发送成功不能直接标记迁移通过。
- 以事件和消费者为核心去重；重复投递只重放同一工作项，不能重复创建迁移任务。
- 忙碌任务按既定策略排队或在安全边界接收；离线任务保留待办，不持续打断正在进行的构建。
- 通知包含接口差异、行为变化、迁移说明、固定候选与摘要、受影响依赖关系、验证入口及关联 PR。
- 用版本化模块文档保存契约；共享状态由控制器维护，不让多个 Agent 编辑一份实时接口文档。

首选路线是利用当前宿主提供的任务消息能力建立受授权的协调适配；本轮只验证了任务查询。官方 App Server 文档提供 thread/resume、turn/start 和 turn/steer，但不证明另启一个 Server 就能安全接管现有 Desktop 活跃任务，接入前仍需针对实际部署验证。

### 3. 自动升级 PR 与验证回传

- 在独立的消费者迁移 Worktree 或 CI checkout 中更新依赖；不改正在开发的 Agent 工作目录。
- 精确修改登记的版本目录或依赖属性，记录原版本、目标版本和基准提交。
- 同一消费者、目标分支和候选工作项只创建一个 PR；重试更新原 PR，禁止重复提交和循环触发。
- 破坏性变更允许先创建草稿 PR，由消费者 Agent 迁移调用并运行验证；失败不修改稳定主线。
- CI 结果必须绑定仓库、PR 提交、工作流运行及尝试编号、实际解析候选和测试结果；不能仅接受远端 JSON 中的 passed。
- PR 合并和稳定组合晋升是后续独立门槛，不把消息送达、PR 已创建或单仓测试通过当作系统发布批准。

GitHub 自动化凭证及事件触发策略须按当前官方规则配置并实测。优先使用授权到目标仓库的 GitHub App；若使用 GITHUB_TOKEN，要验证所选事件是否会触发、是否需要人工批准，不能默认机器人创建 PR 后测试就会自动开始。

## 验收场景

先以三个真实独立仓库和已登记的模块任务跑通，再扩展到十几个：

1. 提供方发布新候选，消费者仍可使用固定旧版本独立构建。
2. 指定 Codex 任务收到一次有效通知，并确认对应候选；无关任务不收到消息。
3. 自动产生或更新唯一升级 PR，记录完整迁移与验证过程。
4. 不兼容候选触发真实失败证据；消费者 Agent 修复后重新验证，稳定主线保持可用。
5. 重启协调器、模拟重复事件、任务离线、发布成功后网络中断，确认可以恢复且不重复发布或创建 PR。
6. 两个消费者都有 :app 时不会串路由；未授权任务、错误仓库和旧提交收据不能确认通过。
7. 所有相关消费者通过后再验证候选组合；真实设备、发布和回滚另行验收。
