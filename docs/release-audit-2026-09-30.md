# 2026-09-30 发布前审查

## 结论

可发布为 Windows x64 本机控制器的源码预览版；不能称为完整跨机器自动协作平台。公开仓库目标为 `aikenchen0-ctrl/worktrunk-agent-runtime`。

本轮只修改独立控制器工程，不修改 SuperAppAndroid 业务模块，不启动十几个真实 Desktop 任务，不向其他任务发送消息，不连接真实设备，也不执行远端 AAR 发布或升级 PR。

## 已修复的阻断项

| 问题 | 修复与验证 |
| --- | --- |
| 多余参数在命令执行后才检查，错误输入可能已经写入状态 | 增加副作用前参数校验；覆盖未知、重复、缺值、身份冲突和转发分隔符 |
| 子命令帮助依赖 Git 环境 | 在 Git 发现前返回帮助；仓库外回归覆盖六个命令 |
| 按路径或分支清理没有正确传递 Worktree 范围 | 修正范围传递；CLI 回归分别验证两个选择器，业务目录与缓存保留 |
| 声明 Rust 1.85，但使用了更晚版本的 let-chain 语法 | 改为兼容写法；Rust 1.85 全目标检查通过 |
| 默认 Hook 忽略精确返回码、嵌套插入分支名、强制清除缓存 | 统一脚本保留返回码，删除路径读 JSON，默认不使用 force 或 purge |
| Windows PowerShell 5.1 错误解析无 BOM 的中文脚本 | 公开 PowerShell 脚本使用 UTF-8 BOM，5.1 解析回归通过 |
| 首次远端 CI 中 PowerShell 7 的模块路径污染 5.1 测试子进程 | .NET 测试启动器移除子进程 PSModulePath，让 5.1 重建默认路径；补测两种父进程 |
| 缺安装器、发布包与摘要清单 | 增加新安装与打包脚本；拒绝覆盖、篡改、越界及并发安装 |
| Cargo 白名单可匹配缓存内同名 README | 改为根目录锚定；检查源码包不包含运行时、缓存、工具与二进制 |
| 控制器 CI 与 Android 消费者模板混放 | 消费者模板移至 examples，控制器 CI 只做 Rust 与发布包检查 |
| 缺许可正文、安全说明和公开使用指南 | 补齐现有双许可证、31 个 Windows 依赖声明、安装与发布边界说明 |

## 本地验证证据

- Rust 1.96.0：`cargo fmt --check`、Clippy 全目标零警告通过。
- Rust 测试：75 项通过，0 失败，包括 62 个单元测试、3 个 CLI 预检测试、7 个消费者路由测试和 3 个组合输出测试。
- Rust 1.85.0：`cargo check --locked --all-targets` 通过。
- Release 二进制构建通过，已产生 ZIP 与 SHA-256；压缩包未签名。
- Windows PowerShell 5.1 发布包回归：11 项通过。包含含空格安装路径、保留旧状态、重复安装拒绝、篡改包拒绝、路径越界拒绝、安装锁、三个 Hook 返回码、删除路径字面传参、非法 JSON 上下文拒绝与脚本解析检查。
- Hook 流程中的失败进程是模拟适配器；不能据此声称真实 Gradle、真机或 Worktrunk 完整生命周期已经验收。
- 源码公开前执行文件白名单、常见凭证特征和 Git whitespace 检查。自动扫描不是完整安全审计，仍需维护者复核。

安装回归的“11 项”把首次安装和状态保留合为一项；脚本解析检查合为一项，不按脚本文件数重复计数。

## 本轮不宣称完成的能力

1. 远端制品仓库事务和服务端禁止同坐标覆盖。
2. 跨机器稳定仓库身份、签名事件和可信 CI 收据导入。
3. Codex 后台通知、断线重试、自动升级 PR、自动合并及稳定组合晋升。
4. 可恢复缓存导入、自动升级器、安装中断自动恢复和二进制签名。
5. 十几个真实 Desktop Agent 同改 API 的完整压力测试、真机验收及 Linux/macOS 完整资源控制。

这些项目保留在跨仓自动化状态与已知限制中，不以 Skill 或接口文档替代其一致性保障。Skill 负责授权后的操作流程，控制器和外部服务负责不能靠 Agent 自觉保证的约束。
