## 工作项与范围

- 工作项 ID、消费者唯一标识、仓库、Gradle 项目、变体：待填写。
- 当前验证修订、上一修订及候选替代原因：待填写；工作项 ID 可保持稳定，但修订证据不能混用。
- 目标分支与本次核对的基准提交、迁移分支、负责 Agent：待填写。
- 提供方交接与原始事件集合：待填写。
- 旧坐标 → 精确候选坐标与 SHA-256：逐项填写全部候选，不写 latest。
- 需要配套的传递依赖或其他候选、实际解析报告：待填写。

## 代码迁移

- 变更原因、调用方式差异、适配与测试修改：待填写。
- 消费者迁移提交完整 SHA、工作区是否干净：待填写。
- 已影响但未覆盖的调用路径、资源、Manifest、R8、JNI 或设备行为：待填写。
- 探索桩或临时适配层是否仍存在：待填写；未用真实候选重验则不能填正式通过。

## PR 与合并前门槛

- PR 状态和地址：未创建 / 草稿 / 开放 / 已关闭 / 已合并。
- 远端头提交是否与本次迁移提交一致：待核对。
- 基准分支推进、rebase、冲突解决或候选变化后是否重验：待核对。
- 阻塞项、下一责任方、保留旧稳定版本或回退步骤：待填写。

仅创建草稿 PR 不代表可以合并。跨仓源码分别合并；合并后的应用按固定候选组合另做集成验收。正式发布批准不由本模板产生。
