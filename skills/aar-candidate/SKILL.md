# AAR 候选发布

产出可追溯、可验证的候选及交接信息，不把接口草稿、编译成功或发布命令退出成功当作完整交付。使用简体中文汇报，代码标识使用英文。

## 入口与边界

1. 读取当前仓库适用的 `AGENTS.md`，确认提供方模块、Git Worktree、目标变体、发布仓库和本次授权范围。只处理指定模块及必要的发布配置；不要修改其他 Agent 的 Worktree。
2. 找到当前安装的 `agentctl`、配套脚本及文档。Windows 默认程序位于 `%LOCALAPPDATA%\agent-runtime\bin\agentctl.exe`。核对实际命令定义；旧版解析器不保证子命令 `--help` 无副作用，参数不明时读取配套源码或 README，不试跑猜测的命令。
3. 从已有配置获取 `AGENT_RUNTIME_ROOT` 和身份，不为同一工作组擅自换根目录。执行 `prepare`、`doctor`，所有构建通过 `run-gradle`。每个 Worktree 使用自己的缓存；独立下载是默认允许的，缓存快照只在项目明确配置时使用。
4. 创建 Skill 或准备候选不等于授权上传。用户已明确要求向指定仓库发布时可在该范围执行；否则先完成本地检查，发布前确认目标与授权。不要打印或复制凭证。

## 契约与版本

1. 读取本模块已发布基线、接口说明、依赖登记和实际 Gradle 配置。区分直接消费者、传递消费者与仅凭静态扫描推测的消费者；找不到完整依赖图时列为待确认，不声称覆盖所有仓库。
2. 使用同一模块范围的 `contract-snapshot`、`contract-diff` 提取差异。当前扫描结果不是完整 Kotlin/Java ABI、资源或行为兼容性证明。补查线程、生命周期、错误语义、序列化、Manifest、资源、JNI 和传递依赖变化。
3. API 可以持续演化。兼容修改与有意的破坏性修改分开记录；后者提供迁移步骤和测试，不要求永远保留旧接口。不兼容比较返回非零时保留证据：它可以阻止稳定升级，但不能被误解为禁止一切候选开发。不得通过重写旧基线隐藏变化。
4. 在提供方自己的版本化文档中记录差异与调用示例，不编辑共享实时接口文档。仅在契约确实变化时更新，不要求每轮对话机械重写。
5. 正式候选从干净、确定的提交构建，记录完整提交和工具链。先提交本次获准的源码、测试和迁移说明，再运行 `candidate-version --base`，直接采用输出；不手工截取 SHA。脏工作区只能产出明确标记的本地草稿，不能冒充该提交的已发布候选。

## 构建、发布、确认

1. 选择本模块真实的构建和测试任务，通过 `agentctl run-gradle -- ...` 执行。记录退出码、测试数量及报告；`help`、零测试或只有 `assemble` 不能说明行为兼容。
2. 优先复用项目已有的 Gradle Maven 发布配置，确认实际 publication 的坐标、变体、版本来源和目标地址。不要仅设置一个未被构建使用的版本属性。需要新增发布配置时，只做本次授权所需的最小变更。
3. 发布 AAR/JAR 以及组件生成的 POM、Gradle 模块元数据和必要依赖。禁止默认共享 `mavenLocal()`、动态候选版本和 `SNAPSHOT`。本机目录仓库只能标记为本机联调；现有测试发布脚本不能代表生产级不可覆盖保证。
4. 远端不可覆盖由仓库服务或已有受控发布机制执行。单纯“检查目录不存在再上传”不是并发保证。坐标已存在时不覆盖；只有来源与所有必要制品摘要匹配才能复用，否则停止并报告冲突。网络失败先检查远端状态，最多进行一次有依据的恢复尝试；不盲目重发或制造新版本掩盖部分上传。
5. 从消费者可访问的入口确认全部必要制品可读，并将下载摘要与本次构建制品比对。带认证的仓库使用已有凭证机制；不把令牌塞入交接 URL。记录验证范围，不把上传退出码当作可消费证明。
6. **制品完整可消费后**才创建 `contract-event`。传入精确版本对应的坐标、下载地址、SHA-256、同模块基线和显式消费者路由。当前版本以本机仓库路径路由，异机身份不匹配必须停在交接阶段，不修改历史事件绕过校验。
7. 保存工具返回的事件标识和文件。重复执行先检查已有候选与事件，复用匹配记录；不因通知失败重新发布。缺失能力列为阻塞项，不虚构发布或通知命令。

具体命令与交接字段见 [命令及交接说明](references/workflow.md)，执行相应阶段前读取。

## 完成报告

- 提供方模块、仓库、完整提交、变体与已验证任务。
- 契约差异、破坏性等级、版本化迁移说明的位置。
- 精确候选坐标、制品与元数据摘要、消费者可访问性证据。
- 事件文件、实际覆盖的消费者及发现依据、尚未验证项。
- 分别说明“本地构建”“远端发布”“事件已生成”“消费者通过”的状态。

候选发布成功不代表消费者迁移完成或稳定组合获准发布。通知与进度协调交给 `aar-coordinate`，调用方迁移交给 `aar-upgrade`；其他 Skill 不可用时输出上述交接内容即可。
