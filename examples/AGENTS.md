# AAR Agent 协作规则

你在一个独立 Git Worktree 中工作。先运行 `agentctl prepare` 和 `agentctl doctor`，所有 Gradle、Maven、ADB 写操作都通过 `agentctl` 入口执行。

## 首次依赖准备

1. 默认在各自私有缓存中独立下载 Gradle、插件和依赖。只有项目明确选择快照方案时，才按配套 `docs/codex-agent-cache-guide.md` 导入已登记的不可变快照，并执行本模块真实任务验证。
2. 每个 Agent 使用稳定唯一的 `AGENT_ID`；所有 Agent 和 Worktrunk Hook 使用同一个短 `AGENT_RUNTIME_ROOT`。
3. 快照只导入空的私有缓存。禁止共享可写 `~/.gradle`、`~/.m2`，禁止复制其他 Worktree 正在使用的缓存。
4. 离线模式发现新依赖时，可以在当前私有缓存联网验证并记录坐标、任务和工具链版本；由缓存维护任务从空种子生成下一版快照，禁止修改旧快照。

## 按需工作流程

- 提供方准备和交付候选时使用 `aar-candidate`。
- 消费者迁移固定候选、验证和交付升级 PR 时使用 `aar-upgrade`。
- 汇总消费者状态、通知已授权任务和组织组合验证时使用 `aar-coordinate`。
- Skill 不提供额外权限或后台调度；发布、推送、建 PR、跨任务消息均服从用户授权。工具或 Skill 不可用时明确报告，不猜测命令。

## 修改接口时必须做的事

1. 先读取本仓库的 `docs/api/README.md`、`docs/api/compatibility.md` 和 `config/dependents.yml`。
2. 修改公开 API、序列化格式、线程模型、错误语义或资源契约时，更新接口说明和迁移说明。
3. 使用 `--module <AAR 模块目录>` 生成契约快照，并与同一模块的最近一次已发布基线比较；禁止拿全仓基线比较单个模块。`contract-diff --enforce` 的破坏性结果应记录并触发迁移计划，不等于禁止有意的破坏性候选开发；稳定升级门槛不能绕过。
4. 候选制品及必要元数据完整发布、从消费者入口可读并核对摘要后，创建或复用对应的 `contract-event`。跨仓消费者通过 `--consumer-targets <路由JSON>` 登记，内容绑定消费者唯一标识、本机仓库绝对路径和 Gradle 项目；不同仓库的同名模块使用不同标识。事件会列出受影响消费者，不要手工编辑其他 Worktree 的接口文档或状态文件。
5. 保留旧接口直到所有消费者完成迁移，或者在兼容性说明中明确记录破坏性变更和迁移步骤。

## 消费候选版本时必须做的事

1. 用 `event-inbox --consumer <模块名>` 读取候选事件，并先确认 `received`。
   本机独立消费者仓库先执行 `event-import --file <事件JSON>`，再读取本地收件箱。导入不会改变路由；旧事件没有显式路由时只能由提供方原仓库验证，跨机器迁移尚不支持。
2. 只在当前 Worktree 修改依赖坐标和调用代码；不要写入 `mavenLocal()`，不要使用 `SNAPSHOT`。
3. 本地迁移过程中可随时构建；正式确认候选前提交迁移代码，保持工作区干净。
4. 调用外挂安装目录中的 `scripts/validate-candidate.ps1`，传入事件文件、消费者名、版本属性、项目路径、实际可解析配置和 JVM 测试任务。脚本负责开始验证、测试和确认；不要自行用 `help`、`assemble`、聚合 `check` 或旧收据填报 `passed`。
5. 提供方或集成 Agent 使用 `event-status` 检查所有消费者是否完成验证；单个事件就绪不代表多个 AAR 候选组合已经兼容。

## 验证多个候选的组合

1. 在集成 Worktree 中提交精确依赖配置；用集成清单指定全部候选事件、项目、解析配置、测试任务和可选构建任务。
2. 运行 `agentctl run-integration --manifest <清单> -- -P<版本属性>=<候选版本>`。任务由清单确定，不能通过命令行换成 `help` 或跳过校验。
3. 联合迁移尚未完成所有消费者确认时，可显式使用 `run-integration --allow-pending-consumers` 探索候选组合；不得为了启动组合测试而伪造 `passed`。
4. 用 `integration-status` 分别读取 `combination_verified`、`ready_for_integration` 和失败原因。探索构建通过但仍有待验证消费者时，前者可为真，后者必须为假，状态命令返回失败。单候选全部通过但没有组合收据时仍不能报告组合通过。
5. 清单、事件、消费者确认或提交变化后重新验证；正在运行和中断的验证不得沿用旧成功状态。
6. 报告必须说明范围：某模块组合通过不等于 App release、真机或所有独立仓库通过。`release_approved: false` 不得改写为已批准发布。

自动调用时使用 `--format json` 并分别收集标准输出与标准错误。`run-integration` 的构建日志进入标准错误，标准输出为收据；前置检查失败时可能没有收据。始终先检查退出码，再解析 JSON，禁止从混合日志中猜测通过状态。PowerShell 版本属性参数整体加引号。

`passed` 必须由对应事件、消费者、提交和本次验证编号的成功收据支持；收据还需包含实际解析的制品摘要及本次执行的测试数量。不要手工创建或复制收据。相同消费者的验证由两小时租约互斥；失败后由原 Agent 报告失败，不能改写别人的状态。

## 接口变更需要交接的信息

- 本仓提交、模块、变更原因；旧签名、新签名、行为变化、破坏性等级。
- 迁移步骤、调用示例、线程/生命周期/错误语义，以及资源、Manifest、序列化和 native ABI 变化。
- 候选坐标、下载地址、制品摘要；发布的 POM 和模块元数据必须包含完整传递依赖。
- 版本必须直接采用 `candidate-version --base <版本>` 的输出；禁止手工截取提交 SHA 拼接。事件中的候选版本必须与 Maven 坐标版本完全一致，URL、坐标和 SHA-256 必须同时提供。
- 已知消费者及发现依据，依赖组合与尚未验证项；不能把阅读通知当成已经迁移。

接口与迁移说明由提供方在自己的仓库提交。禁止多个 Agent 编辑一份共享实时接口文档；由控制器管理事件和确认状态。当前事件字段尚未覆盖以上全部交接信息，缺失部分随版本化迁移文档交付，不能声称已自动分发。

## 状态边界

- 共享仓库文件只保存可审查的规则、接口说明和依赖登记。
- 候选事件、确认状态、锁、租约、Gradle 用户目录和 Maven 临时仓库都在 `AGENT_RUNTIME_ROOT` 外部目录。
- 不依赖某一次 Codex 对话是否收到消息。即时通知丢失时，以 `event-inbox` 和 CI 状态为准。
- 不在没有候选制品的情况下假设其他 Agent 已经实现接口；先继续使用稳定坐标，或等待候选事件。
- 草稿接口允许通过独立的契约桩进行提前开发，但必须明确标记为草稿，最终用真实候选制品重验。
- 依赖图必须检查传递路径；同一模块不得同时来自旧版 `project(...)` 和新版 Maven 制品。

## 完成前检查

```powershell
agentctl doctor
agentctl dependency-audit --enforce
agentctl run-gradle -- check
agentctl status --json
```
